# ADR-013 · 拼音搜索的范围与取舍

- 日期：2026-10-20
- 状态：已接受
- 关联：SDD §1.3（1000 条资产检索 ≤ 50 ms）、SDD P1「拼音搜索」

## 背景

SDD 把「拼音搜索」列为 P1：中文用户在搜索框里输入拼音，应能搜到中文标题的资产。
实现前有两个问题需要决定：

1. 拼音数据从哪来、覆盖到多大范围；
2. 匹配语义是什么（全拼？首字母？分词？），以及它对性能与存储的影响。

## 决策

**1. 数据来源：《通用规范汉字表》2013 年版 8105 字的最常用读音。**

使用 `mozillazg/pinyin-data` 的 `kMandarin_8105.txt`，剥离声调后按
「汉字 + 无声调读音」连续串编码进 `src/core/vault/pinyin-data.ts`（约 7900 条，
字符与读音交替出现，可无歧义顺序解析，解析逻辑有测试固化）。

**2. 匹配语义：段内子串匹配，同时支持全拼与首字母。**

- 文本按「中文字符 / ascii 字母数字」切成连续段，标点空格是段边界；
- 每段产出全拼串与首字母串，段间用 `\u0000` 断开，因此查询不会跨段误匹配；
- 命中判定是「候选串包含查询串」：`zw` 命中「中文」，`zhongwen` 同样命中。

**3. 只影响检索，不影响存储与权限。**

- 不新增可搜索字段、不改 `title` 等字段的加密方式（SDD §5.2 语义不变）；
- `hidden` 卡片仍被 `searchItems` 过滤，拼音分支不绕过可见性；
- 拼音表是纯静态数据，不含任何用户数据。

## 取舍与限制（如实记录）

| 限制 | 原因 | 影响 |
| --- | --- | --- |
| 多音字只取最常用读音 | 表只给一个读音 | 「银行」首字母是 `yx` 而非 `yh`；用 `yh` 搜不到（已有测试固化此行为） |
| 表外字符断开候选串 | 8105 之外的生僻字没有读音 | 「中X文」不会被 `zw` 命中，避免跨生僻字误匹配 |
| 不支持声调、隔音符与分词 | 属增强而非必需 | 输入 `ni'hao` 无法命中「你好」 |
| 中英文之间无空格时视为同一段 | 与用户书写习惯一致 | 「中GitHub」候选为 `zgithub` 而不是两段 |
| 未做索引/缓存 | 1000 条实测远低于 50 ms | 资产规模到数万级时需要重新评估 |

## 备选方案

- **引入 npm 拼音库（如 pinyin-pro）**：功能更全（多音字上下文判别、分词），
  但引入运行时依赖与约 100–200 kB 数据，且把"最常用读音"换成了运行时计算；
  对一个纯本地、只服务检索的场景，收益不成比例。若后续产品要求多音字智能判别，
  再在此决策上替换为库实现，接口（`pinyinCandidates`）保持不变。
- **只做首字母**：数据量减半，但用户输入全拼时命中不了，体验断裂，放弃。

## 后果

- 搜索框现在同时接受：原文、拼音全拼、拼音首字母（大小写不敏感）。
- `src/core/vault/pinyin.ts` 是唯一入口，`search.ts` 的 `matchesText` 在查询为纯
  ascii 字母/数字时才进入拼音分支，避免对中文查询做无谓计算。
- 若需要升级拼音表，重新生成 `pinyin-data.ts` 即可（生成脚本不进仓库，
  数据来源与格式已写在文件头注释里）。
