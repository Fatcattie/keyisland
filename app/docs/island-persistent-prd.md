# 密岛 KeyIsland — 增量 PRD：灵动岛常驻化

> 本文为**增量 PRD**，只描述本次变更。未提及的部分以现有 PRD / SDD 为准，不重述、不改写。

| 项 | 内容 |
| --- | --- |
| 产品 | 密岛 KeyIsland（`keyisland.exe`，安装包 `KeyIsland_x.x.x_x64-setup.exe`） |
| 变更主题 | 灵动岛（Island）从「主窗口内的可收缩预览条」升级为「独立于主窗口的常驻可用桌面小组件」 |
| 变更类型 | 功能增强（窗口形态 / 常驻能力 / 系统集成），非重构 |
| 影响面 | 桌面壳（窗口与托盘）、Island 承载方式、锁定与单实例语义 |
| 不变面 | 加密链路、恢复码流程、主窗口内预览条的功能 |
| 语言 | 中文 |

## 1. 背景与目标

### 1.1 现状（已核实）

- 桌面壳只有一个 Tauri 窗口 `main`；Island 是嵌在 `MainPanel` 内的可收缩预览条，由 `ui-store` 的 `island.phase`（collapsed / expanded / closing）驱动。
- Island 组件本身**功能完整**（搜索、最近使用、快捷建卡、复制密码、生成密码、跳转均有测试覆盖），但**依附于 `main` 窗口**：`main` 一关，岛即消失。
- Rust 侧无第二窗口、无系统托盘、无「关闭即隐藏」；窗口关闭 = 进程退出。已挂单实例插件，第二次启动只把 `main` 拉到前台。
- 现有安全机制须保留并适配：自动锁定（immediate / 5m / 30m / 4h / boot）、切后台与系统锁屏也锁、隐藏卡片二次验密（120s）、批量删除重输主密码、复制 30s 自动清空。

### 1.2 用户原话

> 灵动岛只能预览，不能直接使用是不行的，预览功能要保留，设置成功后可以直接使用灵动岛，主面板可以关掉留在后台，灵动岛则可以鼠标右键唤醒主面板。

### 1.3 本次目标（3 个，正交）

1. **可用**：灵动岛脱离主窗口独立存在，且岛内是**完整可用**的 Island（不只是预览），已解锁时不开大窗口也能完成「找 → 复制 / 新建」。
2. **常驻**：主面板关闭 = 收进系统托盘、进程继续运行、岛仍可见；从托盘或右键岛可随时把主面板叫回来。
3. **不倒退**：主窗口内的原预览条**功能与形态保持不变**；锁定、二次验密、复制清空等安全行为在「主面板隐藏、仅岛可见」状态下依然正确。

### 1.4 已确认决策（不再讨论）

- **决策 A｜后台存活模型 = 托盘 + 灵动岛常驻**：主面板关闭后应用缩到系统托盘，灵动岛窗口仍可见；从托盘图标或右键灵动岛都能重开主面板 / 锁定 / 退出。
- **决策 B｜右键灵动岛 = 弹出小菜单**，含三项：**打开主面板 / 锁定保险库 / 退出密岛**。

## 4. UI / 交互变更说明

### 4.1 灵动岛窗口形态

- 独立窗口，**无系统标题栏/边框**，圆角半透明小组件观感，始终置顶。
- 两种形态：**收起态**（窄条，仅示意「岛」存在）与**展开态**（完整岛面：搜索框 + 最近使用 + 快捷新建入口）。
- 展开/收起沿用现有岛组件既有的动效与延时配置，**不作为本次变更点**。
- 不占任务栏、不出现在 Alt+Tab 列表（与「小组件」定位一致）。
- 可拖动；位置需被记住（CHG-10，P1）。

### 4.2 主窗口关闭行为

| 触发 | 变更后行为 |
| --- | --- |
| 点主窗口关闭按钮（×） | 隐藏主窗口 → 应用留在托盘 + 岛常驻；**不退出进程** |
| Alt+F4 | 同上 |
| 托盘「退出密岛」/ 右键岛「退出密岛」 | 真正退出：进程结束、托盘图标与岛一起消失 |
| 第二次启动 `keyisland.exe` | 不新开实例，把已隐藏的 `main` 显示并聚焦 |

> 注意：本变更改变了「关窗口 = 退出」的既有用户预期，因此 CHG-11（首次提示）虽是 P1，但建议随 P0 一起交付。

### 4.3 托盘

| 项 | 说明 |
| --- | --- |
| 图标 | 与安装包/应用图标一致；常驻通知区 |
| 左键单击 | 打开主面板（P0 行为按「打开主面板」处理，双击同理） |
| 菜单项 | 打开主面板 / 锁定保险库 / 退出密岛 |
| 未建库时 | 菜单第一项引导至建库流程，而不是打开一个空白主面板 |
| 提示 | 悬停显示「密岛 KeyIsland」及当前状态（已解锁 / 已锁定） |

### 4.4 右键灵动岛菜单（决策 B）

| 顺序 | 菜单项 | 行为 |
| --- | --- | --- |
| 1 | 打开主面板 | 显示并聚焦 `main`（若已显示则仅聚焦/前置） |
| 2 | 锁定保险库 | 立即锁定，岛切换到锁定态；已锁定/未初始化时置灰（CHG-09） |
| 3 | 退出密岛 | 结束进程，同时移除托盘图标与岛窗口 |

- 菜单在指针离开后关闭；不得与岛内卡片级菜单（如跳转菜单）同时弹出。
- 现有岛内右键菜单若已有其他条目，需与上述三项**合并为一套菜单**（排序与保留项由架构师核对既有测试后确定，见 R5）。

### 4.5 状态矩阵（主面板 × 岛 × 会话）

| 主面板 | 岛 | 会话 | 期望 |
| --- | --- | --- | --- |
| 显示 | 收起 | 已解锁 | 现有行为不变（预览条 + 热区可用） |
| 显示 | 展开 | 已解锁 | 现有行为不变 |
| 隐藏 | 收起 | 已解锁 | 岛可点击展开并完成全部操作 |
| 隐藏 | 展开 | 已解锁 | 完整岛面可用；失焦/超时后收起 |
| 隐藏 | 收起/展开 | 已锁定 | 岛仅显示锁定态，不含任何资产信息；提供进入解锁的引导 |
| 隐藏 | 不可见 | 未初始化 | 托盘为唯一入口，引导建库 |

## 5. 明确 Out-of-scope

以下内容本次**不改动**，任何实现都不得以「为了常驻」为由触碰：

1. **加密链路**：密钥派生、DEK/KEK、加密存储格式、数据库文件布局、`VaultClient` 的加密语义，一律不动。
2. **恢复码流程**：生成、校验、重置、错误处理与既有 UI 不动。
3. **主窗口内预览条**：功能集合、快捷键、热区配置、收起延时、动画均保持现状（CHG-06 为回归保护项，不是改造项）。
4. **安全策略档位本身**：自动锁定的档位集合与默认值（30 分钟）不新增、不修改；本次只保证其在「仅岛可见」状态下行为正确。
5. **云同步/多端/账号体系**：不做。产品保持纯本地、无服务器、无后门。
6. **岛内新增业务能力**：不新增卡片类型、不改字段、不改搜索排序规则。

## 6. 待确认与风险（仅记录，不在本文决策）

### 6.1 技术风险

| ID | 风险 | 说明 | 需谁确认 |
| --- | --- | --- | --- |
| R1 | 托盘与第二窗口的编译/打包 | Rust 侧新增窗口与托盘需要 `tauri::tray`（Tauri 2 内置）或 `tauri-plugin-tray`；需评估本机 Windows 编译环境、图标资源与 NSIS 打包是否随之变化（安装包体积、快捷方式、开机自启项） | 架构师 |
| R2 | 跨窗口共享会话与 `VaultClient` | 两个窗口是**同一前端 bundle 的两个 webview**，Zustand 内存状态不互通。需在「共享内存状态」与「经 Rust 命令桥接」之间选路。**安全红线**：为共享而把 DEK / 主密码 / 恢复码经 IPC 明文传递或落盘，均不可接受（违背「主密码不落盘」） | 架构师 + 安全评审 |
| R3 | 单实例语义扩展 | 现有 `single_instance` 只负责拉起 `main`；岛常驻后需明确第二次启动不得复制出第二个岛/第二个托盘图标（CHG-08 已写验收，实现路径待定） | 架构师 |
| R4 | 岛窗口的几何与热区语义 | 现有 `hotzone`（顶部热区唤出）与 `collapseDelayMs` 是「主窗口内预览条」的语义；主窗口隐藏时热区无宿主窗口。需明确独立岛窗口是沿用点击展开，还是也保留热区唤出 | 架构师 + 主理人 |
| R5 | 既有右键菜单契约 | `app/src/features/island/__tests__/Island.context-menu.test.tsx` 已存在，说明岛内右键菜单已有既定契约（其条目内容受内容门控未读取）。决策 B 的三项菜单需与该契约合并，避免回归 | 架构师 |
| R6 | 用户预期落差 | 「关闭窗口 = 应用退出」是桌面惯例；改为隐藏后，用户可能以为已退出（安全类产品的误判代价较高） | 主理人（是否把 CHG-11 提为 P0） |

## 7. 交付判定（Definition of Done）

- CHG-01 ~ CHG-08 全部通过验收口径；CHG-06 以**既有测试零回归**为准。
- 安全回归：主面板隐藏状态下，自动锁定、系统锁屏锁定、隐藏卡片二次验密（120s）、批量删除重输主密码、复制 30s 清空，五项逐一验证通过。
- 打包验证：`KeyIsland_x.x.x_x64-setup.exe` 安装后，托盘图标、岛窗口、单实例、退出清理四项在干净环境可用。
- 文档：用户手册补充「关闭主面板后应用去哪了 / 如何彻底退出」。
